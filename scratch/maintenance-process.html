مسار اعتماد طلب الصيانة

من لحظة تقديم الطلب حتى إغلاقه: كل مرحلة، الشخص أو الصلاحية المسؤولة عن القرار فيها، والحالات (Status) الكاملة التي يمر بها الطلب بالنظام.

إعداد: ديمة العثمان التاريخ: 15 سبتمبر 2026 المسار: Requests / Maintenance

من يقدّم الطلب؟

أي موظف لديه حساب دخول مرتبط بسجل موظف بالنظام — بدون أي صلاحية خاصة. يعبّي: مكان العمل، نوع الأصل، وصف العطل، ومستوى الأولوية (عاجل / متوسط / عادي).

موافقة المدير المباشر

PENDING_MANAGER
يقرر فيها: المدير المباشر لمقدّم الطلب

يصل إشعار للمدير المباشر (يُحدَّد تلقائياً من شجرة الإدارة بالنظام — لا حاجة لصلاحية خاصة)، ويوافق أو يرفض الطلب.

← عند الموافقة PENDING_LOGISTICS
← عند الرفض REJECTED (نهاية المسار)
٢

قرار المسؤول اللوجستي

PENDING_LOGISTICS
يقرر فيها: أي حامل صلاحية requests:lo-approve

بقرار واحد، المسؤول اللوجستي: يوصّف الحالة، يختار نوع الإصلاح المناسب، ويعيّن الموظف المكلَّف بالتنفيذ (+ المبلغ المتوقع إن وُجد).

دمج تلقائي: إذا كان المدير المباشر لم يوافق بعد، وصاحب صلاحية اللوجستي هو نفسه المدير المباشر لمقدّم الطلب، يوافق النظام عن المرحلة الأولى تلقائياً بنفس الخطوة.

نوع الإصلاح المختار يحدّد المسار التالي مباشرة:

← ASSIGNED مباشرة

قطع خارجية / ورشة خارجية

INTERNAL_PARTS · EXTERNAL_WORKSHOP

← يعتمد على قيمة المبلغ
  • المبلغ ≤ 100$ (أو بدون مبلغ)، أو المدير المباشر هو نفسه المدير التنفيذي ← تخطٍّ تلقائي إلى ASSIGNED
  • المبلغ > 100$ ← ينتقل الطلب إلى PENDING_EXECUTIVE
٣

موافقة المدير التنفيذي

PENDING_EXECUTIVE مشروطة
يقرر فيها: أي حامل صلاحية requests:ceo-approve

تظهر هذه المرحلة فقط عندما يحتاج الإصلاح قطعاً أو ورشة خارجية بمبلغ يتجاوز 100$. المدير التنفيذي يوافق أو يرفض.

← عند الموافقة ASSIGNED + إشعار تلقائي للمدير المالي (requests:cfo-approve)
← عند الرفض REJECTED (نهاية المسار)
٤

قيد التنفيذ

ASSIGNED
ينفّذ فيها: الموظف المكلَّف (المعيَّن بالمرحلة الثانية)

الموظف المكلَّف ينفّذ أعمال الصيانة، ثم يضغط "تم التنفيذ" لإغلاق الطلب. لا يستطيع أي شخص آخر إغلاق المهمة نيابةً عنه.

← عند الإنجاز DONE
